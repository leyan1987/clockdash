# ClockDash · 小红书 Vibecoding 大赛视频内容概况（两版）

> 时长：1–2 分钟｜竖屏 9:16｜小红书风格

## 先说这个项目最吸引人的点（按传播力排序）

1. **旧物复活的故事感**：13 年前、512MB 内存的老平板，别人当电子垃圾，你把它变成全家信息中枢——天然的"变废为宝"钩子
2. **极致工程的数字冲击**：250KB 的 APK（微信的 1/300）、零第三方框架、内存 10–20MB、CPU 占用≈0——数字自带传播力
3. **温情的使用场景**：吃降压药提醒、给妈妈打电话、农历+调休标班休——是给爸妈做的产品，情感共鸣强
4. **和比赛主题完美契合**：全程用自然语言和 AI 对话完成 App + 服务器 + 网页后台，是 Vibecoding 的标准案例
5. **技术巧思有故事**：老安卓只有 TLS 1.0 连不上现代 HTTPS → 让服务器代抓天气——"AI 一起解决 13 年前的兼容问题"很出圈

## 版本 B：《我做了一个只有 250KB 的安卓 App》—— 硬核技术向（约 90 秒）

**定位**：面向程序员/极客圈层，靠数字和工程决策建立"狠活"信誉。

| 时间 | 画面 | 口播/字幕要点 |
|---|---|---|
| 0–5s | 屏幕中央超大数字「250KB」 vs 对比条：微信 vs 本 App | "我用 AI 做了一个 250KB 的安卓 App，装在 13 年前、512MB 内存的平板上，流畅得像新机。" |
| 5–20s | 三栏看板设计图 + 系统架构图逐层点亮（平板 → Python 服务器 → 高德/holiday-cn） | "它是什么：常亮的时钟看板——农历+法定节假日调休、天气、循环待办、全屏提醒，再加一个手机网页后台。" |
| 20–50s | **三个硬核点快剪**：① 架构图高亮"服务器代抓 HTTPS" ② 代码滚动 + 测试终端打钩（LunarTest 40/40）③ 手机实拍：锁屏弹出全屏提醒 | "三个狠活：一，老安卓只有 TLS 1.0，现代 HTTPS 全握手失败——我让服务器代抓天气，平板只说 HTTP；二，农历不依赖网络，离线算法覆盖 1900–2049，40 个真实节日锚点测试全过；三，循环待办引擎 + 精确闹钟，锁屏也能弹出全屏提醒。" |
| 50–75s | 屏录：自然语言对话 → AI 生成纯原生 Java 代码；测试统计表 | "全程 Vibecoding：AI 写的代码零第三方框架、零 WebView、零图片资源，全部原生 View。26 项循环引擎测试 + 40 项农历测试，66 项全绿。" |
| 75–90s | 双 APK 并排展示（legacy / modern）+ GitHub 页面 + 墙上成品 | "还做了双版本，适配新手机平板。项目开源 MIT 协议——想复活你家吃灰平板的，评论区扣 1。" |
